# Benchmarks

Three independent measurements live here:

1. **Token savings** — deterministic, no model needed.
2. **Answer quality A/B** — needs an OpenAI-compatible endpoint you run yourself.
3. **Engine speed** — deterministic, no model needed.

All data is synthetic and generated by a seeded LCG in
`src-tauri/examples/shared/bench_data.rs`. No real or private data is used.

## 1. Token savings (no model required)

```bash
cargo run --manifest-path src-tauri/Cargo.toml --example bench_public --release
```

This prints a table and writes `bench/results/token-savings.md`. It covers
JSON, JSONL, CSV, logfmt, markdown table, XML, SQL, INI, TOML, YAML, plus two
control cases (plain prose and a fenced code block) that must come out
unchanged.

Token counts use the `cl100k_base` tokenizer. Other tokenizers (Claude, Gemini,
Llama) will give different numbers, so do not copy these percentages into a
claim about another model without re-measuring.

## 2. Answer quality A/B (bring your own model)

### Step 1 — dump the cases

```bash
cargo run --manifest-path src-tauri/Cargo.toml --example bench_dump --release
```

This writes `bench/out/cases.json`: for each dataset, the raw prompt, the
compressed prompt the engine actually produces, and a handful of questions
(`lookup`, `count`, `max`, `sum`) whose expected answers are **computed from the
generated data**, not hand-written.

### Step 2 — run your model

Any OpenAI-compatible `/chat/completions` endpoint works: Ollama, llama.cpp's
`llama-server`, LM Studio, vLLM, or a cloud provider.

**Ollama**

```bash
ollama serve                 # in one terminal
ollama pull llama3.2
OPENAI_BASE_URL=http://127.0.0.1:11434/v1 MODEL=llama3.2 node scripts/bench-quality.mjs
```

**llama.cpp (`llama-server`)**

```bash
llama-server -m model.gguf --port 8080 --chat-template chatml
OPENAI_BASE_URL=http://127.0.0.1:8080/v1 MODEL=local node scripts/bench-quality.mjs
```

**LM Studio** — start the local server (default port 1234), then:

```bash
OPENAI_BASE_URL=http://127.0.0.1:1234/v1 MODEL=<model-id> node scripts/bench-quality.mjs
```

**Cloud provider**

```bash
OPENAI_BASE_URL=https://api.openai.com/v1 MODEL=gpt-4o-mini OPENAI_API_KEY=sk-... \
  node scripts/bench-quality.mjs
```

Other environment variables:

| Variable | Meaning | Default |
|---|---|---|
| `REPEATS` | Repeats per question | `3` |
| `CASES` | Comma-separated dataset names to run | all |

### What it measures

Three conditions per question, at `temperature=0`:

- `RAW` — the original data.
- `COMPRESSED` — the engine's real output, decoder instruction included.
- `RAW_REPEAT` — the raw data again; this is the A/A noise floor.

Scoring is normalised exact match (whitespace, case, and number formatting are
ignored). Output:

- `bench/results/quality-<date>.csv` — one row per answer.
- `bench/results/quality-<date>.md` — accuracy per question kind with a 95%
  Wilson confidence interval, plus `RAW−REPEAT` (noise) and
  `RAW−COMPRESSED` (effect) side by side.

If the endpoint is unreachable the script exits with a clear error and writes
nothing. It never invents results.

### How to read the result

Compare `RAW−COMPRESSED` against `RAW−REPEAT`. If the difference is inside the
noise band, the run did not show an effect — say so. Increase `REPEATS` and the
number of cases before drawing any conclusion.

## 3. Engine speed (no model required)

Measures the throughput of the lossless pipeline (segmentation → transform →
verify → decide) on synthetic telemetry blocks — useful when changing engine
internals, to see whether a change cost latency.

```bash
cargo run --manifest-path src-tauri/Cargo.toml --example bench_engine --release

# Thread-pool comparison (output must be identical; only the duration differs):
TLM_ENGINE_WORKERS=1 cargo run --manifest-path src-tauri/Cargo.toml \
  --example bench_engine --release
```

It reports ms per request, token counts before/after with the savings
percentage, whether compression applied, and a serial-tokenize baseline for
bottleneck comparison. It is a developer tool, not a benchmark protocol:
results depend on the machine, so only compare runs from the same machine.
